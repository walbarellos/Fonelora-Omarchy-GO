## Finding F-011 — libfonescout.so (arm64, sem root)

Lib JNI nova que aciona ações de jogo via API il2cpp **em runtime**, dentro do
processo do Pokémon GO 0.433.1.

Localização: `fonescout/native/fonescout.c` + `il2cpp_api.h` + `fonescout_pin.h`.

Por que não precisa do dump em tempo de build:
- símbolos il2cpp → `dlsym` na `libil2cpp.so` já carregada pelo Unity (18 funções)
- classes/métodos → `il2cpp_class_from_name` + `il2cpp_class_get_method_from_name`
- instâncias de serviço → Zenject `ProjectContext.Instance.Container.Resolve(Type)`
  (não-genérico — evita inflação genérica em `Resolve<T>()`)

Pontos-chave (E-003):
- `RpcHandlerExt.Send<In,Out>` colapsa num blob nativo compartilhado; o
  `MethodInfo*` com contexto genérico real é fixado por par em `fonescout_pin.h`
  (`kRpcPins`) — **pendente WI-010** (hoje as ações SendRpc devolvem
  "rpc-no-pin-or-timeout" até calibrar).
- Resposta lida por **poll** de `Promise<T>.completeCalled`/`completedValue`
  (offsets via `il2cpp_field_get_offset`) — sem delegate managed, sem
  `Marshal.GetFunctionPointerForDelegate`.
- Inventário via `IItemBag.GetItemCount` (serviço do jogo) — não decodifica
  `GetHoloholoInventoryOutProto` (oneof ByteString).
- `JNI_OnLoad` dispara thread de init com retry (~60s) porque o Unity carrega
  il2cpp **depois** do JNI_OnLoad.

Exporta 10 funções JNI: `status`, `getItemCount`, `getNearby`, `startEncounter`,
`throwBall`, `fleeEncounter`, `spinFort`, `dropItem`, `evolvePokemon`,
`favoritePokemon` + `JNI_OnLoad`. Compila limpo (sem warnings) via NDK r27c,
`aarch64-linux-android31-clang`, `-O2 -fvisibility=hidden`, strip (`-s`).

## Finding F-013 — Repack multidex + assinatura própria

`fonescout/build.sh` — pipeline reproduzível de 6 passos:
1. libfonescout.so (NDK r27c, arm64)
2. classes Java → classes3.dex (javac + d8)
3. apktool decode do plugin.apk → patch smali do registro → apktool build
4. injeta classes3.dex + lib/arm64-v8a/libfonescout.so no plugin.apk
5. troca assets/plugin.apk dentro do pokemon_custom.apk
6. zipalign -p 4 + apksigner (keystore própria `fonescout.keystore`)

Decisão multidex: o dex novo vai como `classes3.dex` separado (plugin já é
multidex: smali + smali_classes2). ART Android 8+ (alvo Android 14) carrega
todos os `classes*.dex` nativamente — **evita baksmali** (que só tinha lib sem
main no Maven; o apktool o sombreia e não expõe main).

Sem duplicatas: `BaseRequest`/`BaseResponse` ficam só como *type references*
em classes3.dex; as definições vivem no classes.dex original do plugin. Verificado
com `dexdump`: 13 descritores de classe, todos `Lcom/android/jmq/impl/gamebot/*`.

Saída: `fonescout/build/out/pokemon_custom_fonescout.apk` (186MB), assinado com
`CN=fonescout` (keystore nova, RSA 2048, validade 10000d). A assinatura difere
da debug original → instalação exige `adb uninstall` prévio; o `restorePlayData`
do plugin recupera o save.
